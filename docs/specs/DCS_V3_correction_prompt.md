## Role and task

You are reviewing and rewriting a design spec for a synthetic decompression-sickness (DCS)
dataset. The current spec ("V3") proposes bolting a Physics-Informed Neural Network (PINN)
onto an existing Bühlmann-ZHL-16C + logistic pipeline ("V2") to add nitrogen-bubble-dynamics
features. The spec is technically polished but contains one fatal conceptual flaw, an
inappropriate use of a PINN, several physics errors, and some methodological problems.

Your job is to produce a **corrected design spec** that (a) removes the PINN, (b) fixes the
physics, (c) makes the new bubble features actually carry signal, and (d) states the
validity limits honestly. Do not rubber-stamp the original. Where the original is right,
keep it; where it is wrong, fix it and say why.

## Context you need

- The entire dataset is **synthetic**. There is no real dive-outcome data and none will be
  available. Labels are generated, not observed.
- V2 pipeline: a Bühlmann ZHL-16C simulator computes nitrogen loading in 16 tissue
  compartments and a continuous `physics_risk_score`; a logistic model converts that score
  plus physiological factors into `dcs_probability`; the binary `label` is a Bernoulli draw.
  The V2 logistic **slope is 9.0** and intercept is **−7.5** (per the V2 reference docs).
- V3 wants to add bubble nucleation/growth physics, which Bühlmann genuinely does not model.
  That motivation is correct and should be preserved. The execution is what's broken.

## Problem 1 (FATAL) — the bubble features carry no new information about the label

The V3 plan derives six bubble features as a deterministic function of the Bühlmann nitrogen
load (it even sets "`R_max` correlates with `physics_risk_score`, r > 0.6" as a success
criterion), then fits their coefficients by regressing against the **V2 labels**. But the V2
labels were generated by a logistic model that contains *zero* bubble physics — they cannot
encode any bubble-dynamics signal. So the regression can only recover the portion of the
bubble features that correlates with `physics_risk_score`, which already drives the label.
This is re-encoding existing information as a nonlinear transform of itself and then
"discovering" it predicts a label defined from the original. Step 3's intercept
recalibration then resets the marginal label distribution back to the V2 targets, so the
dataset ends up informationally near-identical to V2.

**Required fix:** If bubble physics is to matter, the **labels must be regenerated from a
model that includes bubble load** — not regressed against V2 labels that were defined without
it. Redesign the labelling so bubble features enter the data-generating process, so they
carry signal by construction. Make this the central change of the rewrite.

## Problem 2 — do NOT use a PINN; use a numerical ODE integrator

Remove the PINN entirely. Reasons, all of which the rewrite should state explicitly:

1. **No problem that a PINN solves is present.** A PINN earns its place when the governing
   equation is hard/expensive to solve, when there are unknown parameters to infer (inverse
   problem), or when sparse noisy real data needs physics regularisation. Here the bubble
   model is a coupled ODE in one state variable over time, every parameter is specified, and
   there is no real data. None of the three conditions holds.
2. **It is strictly dominated by direct integration.** The coupled bubble ODE can be solved
   per profile with a stiff solver (`scipy.integrate.solve_ivp`, method `BDF` or `Radau`) —
   exactly, with no training, in milliseconds per dive (minutes for all 50,000). The PINN
   needs ~4 h of training only to produce a *less accurate approximation* of the same
   solution. The spec itself concedes PINN inference is "milliseconds," so there is not even
   a speed argument.
3. **It is the hard kind of PINN.** A 27-input parametric surrogate queried at arbitrary `t`
   is far harder than the single-instance PDEs in Raissi et al. (2019) and frequently fails
   to generalise over high-dimensional input spaces.
4. **It targets a known PINN failure mode.** The mechanical equation (Rayleigh-Plesset) is
   stiff on ascent. Krishnapriyan et al. (2021) — cited in the original spec as *support* —
   is in fact a catalogue of how PINNs *fail* on stiff problems. Stiff ODE solvers are
   purpose-built for exactly this and are far more reliable.

Replace the entire "PINN Network Design," "Training Strategy," and PINN-loss-weight sections
with a deterministic numerical integration scheme.

## Problem 3 — physics errors to fix

- **Rayleigh-Plesset is the wrong equation for this timescale.** RP models inertial bubble
  dynamics (cavitation/collapse) on µs–ms scales. DCS bubbles grow over *minutes*; the system
  is overdamped and the inertial terms (`R·R″ + 3⁄2 R′²`) are negligible by many orders of
  magnitude. Use **diffusion-limited growth (Epstein-Plesset) with quasi-static mechanical
  equilibrium**, consistent with the decompression-bubble literature (Van Liew; Gernhardt;
  Srinivasan et al.). Drop the inertial RP solve.
- **The Epstein-Plesset forcing term is dimensionally wrong.** `peak_tissue_sat` is a *partial
  pressure* (bar) in the Bühlmann model, not a molar concentration. `C_∞ = max(tissue_sat) ·
  ρ_blood / M_N2` treats a pressure as a concentration. Convert properly with **Henry's law**
  (`C = P × solubility`) before forming the diffusion gradient `(C_∞ − C_s)`.
- **The initial nucleus radius is ~10× too large.** Yount's VPM nuclei are sub-micron
  (~0.5–1 µm). `R₀ = 10 µm` is a grown bubble, not a nucleation radius. Use a sub-micron `R₀`
  and cite the VPM value correctly.
- **`bubble_n_critical` formula contradicts its own validation check.** `N₀·exp(−R_crit/R_max)`
  is smooth and strictly positive for all `R_max > 0`; it never reaches zero and has no
  threshold at `R_crit`. The validation check "`n_critical = 0` when `R_max < R_crit`" can
  never pass. Either use a genuine thresholded/excess-radius nucleation expression or fix the
  check to match the chosen formula — make them consistent.
- **`bubble_velocity` is mislabeled and marginal.** The formula is Stokes' *terminal buoyant*
  velocity, not "Stokes drift" (a wave phenomenon). Buoyant rise of a ~50 µm bubble is tiny
  next to blood-flow velocity (cm/s), so it will not govern where bubbles lodge. Either drop
  this feature or justify it against blood-flow transport, and rename it correctly.

## Problem 4 — methodology and bookkeeping

- **Remove the isotonic-ordering step.** Forcing fitted coefficients to match a pre-decided
  literature ordering overrides the data with a prior and calls it validation. With labels
  that contain no bubble signal it is fitting noise to a predetermined shape. If the
  regenerated labels (Problem 1) genuinely carry bubble signal, let the data speak instead.
- **Drop the cargo-cult loss weights.** `λ_EP = λ_RP = 0.1, λ_BC = 10` are presented with
  confident citations that do not prescribe those values; Wang et al. (2022) argues for
  *adaptive* weighting, not a fixed 0.1. (Moot once the PINN is removed, but do not carry the
  reasoning forward.)
- **Resolve the slope inconsistency.** The spec states "the slope (18.31) is unchanged," but
  the V2 reference documents a logistic slope of **9.0**. Reconcile this explicitly; an
  unexplained silent drift in the calibration is a red flag that must be fixed before any
  recalibration is trusted.

## What to preserve

- The core motivation: Bühlmann lacks bubble mechanics, and adding a bubble layer is a
  legitimate improvement.
- Sensible engineering: file layout, dependency pinning, reproducible seeding, the V2
  structural and physiological directional validation checks.
- Real, relevant citations (Epstein-Plesset, Yount, Van Liew, Howle, Weathersby, etc.).

## Honesty ceiling — state this in the rewrite

No decompression model is derived from first principles; all are semi-empirical and calibrated
to real dive-trial outcomes. This dataset is synthetic, so a more elaborate bubble model makes
it more *internally sophisticated*, not more *validated*. The bubble features and labels cannot
be checked against real DCS outcomes without real dive logs. The defensible framing is a
**physically-consistent, literature-calibrated synthetic benchmark** for DCS-risk methods — not
an accurate or clinically valid DCS predictor. Scope all claims accordingly.

## Deliverable

Produce a corrected V3 design spec that:
1. Replaces the PINN with a per-profile numerical integration of a diffusion-limited bubble
   growth model with quasi-static mechanics, fixing all Problem-3 physics errors.
2. Regenerates the DCS labels from a data-generating model that incorporates bubble load, so
   the bubble features carry signal by construction.
3. Removes the isotonic-ordering and PINN-loss machinery and resolves the slope inconsistency.
4. Keeps the engineering scaffolding and the honest scoping statement.
Explain each change and why, in line with the reasoning above. Flag anything in the original
spec you cannot verify rather than inventing a justification.
