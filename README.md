## 1. The domain, in one paragraph

Divers breathe air under pressure. Pressure pushes nitrogen into the body's tissues.
If a diver surfaces too fast, that nitrogen comes out of solution as bubbles — this is
**decompression sickness (DCS)**, "the bends." Dive computers run a model
(**Bühlmann ZHL-16C**) that tracks nitrogen in 16 imaginary "tissue compartments" and
tells you how slowly to ascend. The question this project asked: **does that physics
actually predict who gets sick?**

---

## 2. What this project originally was, and why that changed

**Original goal (V2/V3):** build a *synthetic* (fake) DCS dataset. A Bühlmann simulator
produced a `physics_risk_score`; a logistic model turned that plus invented physiological
factors into a probability; labels were coin-flips from that probability. "V3" proposed
bolting a **PINN** (Physics-Informed Neural Network) on top to add nitrogen-bubble physics.

**The V3 plan was fatally broken.** It was reviewed and rewritten. The key defects:

1. **Circular reasoning (fatal).** V3 derived bubble features from the Bühlmann nitrogen
   load, then fit them against the **V2 labels** — labels generated by a model containing
   *zero* bubble physics. The bubble features therefore *could not* carry new signal. It
   was re-encoding existing information as a transform of itself, then "discovering" it
   predicted a label defined from the original.
2. **The PINN was the wrong tool.** The bubble model is a simple ODE with every parameter
   known and no real data to regularise against. A stiff ODE solver (`scipy.solve_ivp`)
   solves it *exactly* in milliseconds. The PINN needed ~4 h of training to produce a
   *worse* approximation of the same answer.
3. **Physics errors.** Rayleigh-Plesset (a microsecond cavitation equation) was used for
   bubbles that grow over *minutes*; a partial pressure was treated as a concentration
   (missing Henry's law); the starting bubble radius was ~10× too large.
4. **Fabricated statistics** in the supporting docs. Retracted (commit `a00bf78`).

**The pivot that matters:** rather than perfect a fake dataset, the project turned to
**2,700 real dives with real DCS outcomes** (US Navy NMRC 99-02 trials) and asked the
falsifiable question: *does any of this physics actually work?*

---

## 3. THE ANSWER — the single most important thing in this document

**No. The physics does not work on real data.**

A rigorous benchmark was built and run. Results (`RESULTS.md`, generated, do not edit):

| Algorithm | Metric | Verdict | ΔAUC |
|---|---|---|---|
| `zhl16c` (standard Bühlmann) | risk_index | **NOT SUPPORTED** | +0.0068 |
| `zhl16c` | deficit | **NOT SUPPORTED** | −0.0083 |
| `zhl16c_gf` (gradient factors 30/70) | risk_index | **NOT SUPPORTED** | −0.0038 |
| `zhl16c_gf` | deficit | **NOT SUPPORTED** | +0.0010 |
| `ep_bubble` (bubble model) | risk_index | **NOT SUPPORTED** | −0.0002 |

Every algorithm failed. The **bubble layer — the entire point of V3 — earns nothing**
(−0.0002). Bühlmann adds nothing beyond the raw dive numbers.

**What *does* carry signal:** the three plain numbers (depth, bottom time, ascent time)
give **AUC 0.6425**. Interpretation: given one diver who got sick and one who didn't, the
model ranks them correctly ~64% of the time. Coin-flip is 50%. A useful clinical test is
0.85+. So: **weak, but real.** The physics adds nothing on top of it.

**This prediction was pre-registered** in the design spec *before* implementation, and it
held. That is a legitimate, well-controlled **negative result** — not a failure.

### The trap you must not fall into

The **physiological factors were never tested against a single real outcome.** The real
dive CSV contains only:

```
data_set, profile_number, outcome, depth_fsw, bottom_time_min,
ascent_time_min, T1_min, T2_min, n_raw, dive_id, quality_flags, source_page
```

**There is no age, weight, BMI, sex, or fitness in the real data.** Physiological factors
existed *only* in the synthetic dataset, where the user invented both the factors and the
answers. Of course they "worked" there — the rules were written, then confirmed. That
proves nothing. **Do not claim physiology is validated. It is not.**

## 5. Why the benchmark is trustworthy (the anti-fooling-yourself machinery)

This is the real intellectual content. Do not weaken any of it.

- **Nested grouped cross-validation.** Splits are grouped by `data_set` (dive trial).
  Trials differ in how aggressive their protocols were; pooling them would leak trial
  identity into the estimate and inflate the score.
- **Four gates.** An algorithm must clear *all* of: effect **magnitude** (|ΔAUC| > 0.03 —
  fold sd is ~0.06, so anything smaller is noise), **significance** (p < 0.05), **fold
  consistency**, and **coefficient sign** (it must help in the direction the physics says).
- **Three standing controls.**
  - *Label shuffle* → must land at AUC ≈ 0.5 (measured 0.5230). If it doesn't, something leaks.
  - *Leakage gap* (ordinary CV − grouped CV) → +0.0440. This is exactly the inflation
    grouping prevents.
  - *Baseline* (logistic on the 3 raw features) → the bar every algorithm must beat.
- **Permutation nulls.** Each result is compared against permuted-label runs.
- **Dual reconstruction.** The 3 recorded scalars do **not** determine a dive profile. Two
  reconstructions are built (`linear`, `staged`); `staged` is measurably closer to the real
  curves (median RMSE **36.08** vs **48.71** fsw over 72 gold curves, Wilcoxon
  **p = 1.8e-11**) — *but it still only beats predict-the-mean on 44.4% of dives.* So every
  claim is **gated on both reconstructions agreeing**. Sensitivity can only *demote* a verdict.
- **Provenance discipline.** `RESULTS.md` is generated. `python scripts/run_benchmark.py
  --marginal exclude --check` regenerates and diffs; it exits 1 on drift. (It deliberately
  ignores the `git:` and `command:` lines, which are informational only.)
  `check_doc_numbers.py` extends the same guard to numbers quoted inside the prose docs.
- **Honest reporting of a dirty exclusion.** 470 saturation / >300 fsw dives are excluded
  on *physiological* grounds (a single-nucleus bounce model doesn't represent them). Their
  DCS rate was **24.3% vs 13.7%** for those kept — **the exclusion is outcome-correlated**,
  so it is reported in RESULTS.md rather than hidden.
- **Never emits a probability.** AUC is a *ranking*. The ~16% DCS rate reflects Navy trials
  *designed to provoke DCS*. This is not a dive-planning tool and must never be presented
  as one.

## 6. Hard-won lessons — DO NOT REPEAT THESE MISTAKES

1. **Do not reintroduce the PINN.** It was removed for good reasons (§2). A stiff ODE
   solver dominates it on every axis.
2. **Do not duplicate the Bühlmann table.** Import from `benchmark/buhlmann.py`. Four
   copies once silently diverged (Correction 10).
3. **Do not generate a test fixture from this implementation and then use it to test the
   implementation.** That is how `test_table_compartment16` came to guard the very bug it
   should have caught. A known-missing test (a published US Navy table fixture) was left
   *deliberately unshipped* rather than faked — that is the honest choice.
4. **Do not hand-edit `RESULTS.md`.** It's generated; `--check` will catch you.
5. **Do not "fix" the negative result.** If someone tunes the pipeline until an algorithm
   scores SUPPORTED, that is p-hacking. The spec says explicitly: *if any algorithm reaches
   SUPPORTED, do not celebrate it* — re-run with more repeats, inspect the coefficient sign,
   and check the permutation null before believing it.
6. **A `constant` algorithm cannot be the extensibility demo.** Zero variance *raises*
   `AlgorithmError` by design. The demo is `noise` (has variance, carries no signal). The
   original spec asked for both and was self-contradictory; this was fixed.

## 7. How to run things

```bash
cd /Users/aryankabra_test/Desktop/DCS_PINN_DATASET_V3

# Full test suite (~2 min; permutation nulls dominate)
/opt/miniconda3/bin/python3 -m pytest -q                      # expect: 65 passed

# Regenerate results (~4 min)
/opt/miniconda3/bin/python3 scripts/run_benchmark.py --marginal exclude

# Provenance gate — exits 0 if current, 1 if drifted
/opt/miniconda3/bin/python3 scripts/run_benchmark.py --marginal exclude --check

# Reproduce the reconstruction finding
/opt/miniconda3/bin/python3 scripts/validate_reconstruction.py
# expect: median RMSE linear 48.71 / staged 36.08, staged better on 83.3%
```

`--marginal` has **no default** — you must state the rule explicitly. That is intentional.

One expected warning: a scipy `RuntimeWarning` from `test_constant_feature_fails_and_nan_pvalue_is_handled`.
It is *supposed* to fire — that test forces a NaN Wilcoxon p-value to prove the significance
gate **fails** rather than silently skips.

## 9. The honesty ceiling — always state this

No decompression model is derived from first principles; all are semi-empirical and
calibrated to real dive trials. A synthetic dataset with fancier bubble physics is more
*internally sophisticated*, **not more validated**. Nothing here is a clinically valid DCS
predictor, and the real data lacks the physiological variables needed to build one.

The defensible framing is: **a physically-consistent, literature-calibrated benchmark for
DCS-risk methods.** Scope every claim accordingly. When in doubt, understate.
